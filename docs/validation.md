# 验证范围

CI 验证与实体设备验证分开记录。

## 自动检查

- Windows x64 / ARM64：在对应架构发布自包含应用、运行协议及状态自检、核对最终 PE 机器类型。
- Mac arm64 / x86_64：在对应架构执行 Swift 测试，编译完整 SwiftUI 应用及 USB 库，核对两个 Mach-O 文件架构，验证签名并执行最终包内的 `--version`。
- Mac 两架构均从 Swift 编译器常量输出提取 App Intents 元数据，校验最终包内五个动作和状态实体，执行不接触 USB 的结构化状态与 App Shortcuts 检查。
- Mac 并发回归检查：界面与系统动作不能同时写 USB；写操作期间的查询不启动新硬件读取；写入失败清除旧成功状态；写入前已启动的迟到查询不能覆盖新模式。
- Apple Silicon runner 使用真实 NSHostingView 离屏渲染系统控件预览。它不截取用户桌面；预览成功不等于完成 VoiceOver、Siri 或全状态视觉验收。
- 两端使用同一份 AT 响应样本，包含正常值、拒绝、缺少确认、错误键、不支持的模式。
- Mac USB 传输仅允许已知型号和已知 AT 接口，写指令有精确白名单，不接受通用终端命令。
- 绿色状态要求模式、自动联网、实际 USB 协议和匹配到模块的网络地址都已确认。Windows 沿用已实测的设备识别和 NDIS 地址检查。

## 实体设备

原 Windows x64 2.1 版的相同控制流程曾在 DJI 第一代模块验证模式往返、自动联网恢复、USB 类型和绑定源地址的连通性。参考耗时：切回 Mac/iPad 约 2 秒；Windows 取得地址约 37.5 秒。

3.0 的 Windows 运行时升级到 .NET 10；自动测试会覆盖所有构建架构，但不能替代设备连通测试。Mac 两种架构和 Windows ARM64 的首次公开发行均属于待实物验证的测试版。

Mac 的 IOKit 网络检测只查看 USB 祖先匹配 `2CA3:4006` 的接口，不会把 Wi-Fi 的地址当成模块上网成功。检测有效 IPv4 不代表外网出口一定正常。

实体测试应核对：只接一张模块、正常/占用/缺失状态、每个方向至少一次往返、恢复初始模式、取得地址后绑定目标接口测试出口、插回 iPad 的实际可用性。

## Mac 无障碍与系统集成待实机验收

已实现原生 Toggle / Menu / Button、语义状态标签、VoiceOver 重要状态播报、键盘快捷键、无颜色依赖的文字与图标反馈，以及减少透明度、增强对比度、减少动态效果适配。独立面板可调整大小并滚动。以下人工项目尚未在真实 Mac 完成，不能将这些实现描述为无障碍认证：

- VoiceOver 遍历菜单栏、开关、更多菜单、状态和刷新按钮，核对名称、值、焦点顺序、禁用状态；轮询不应反复播报，切换开始与结果应可感知。
- 开启“键盘导航”，用 Tab / Shift-Tab / Space 与快捷键操作；在菜单栏面板和独立面板分别检查焦点可见性、窗口切换及关闭后重新打开。
- 明暗模式、增强对比度、减少透明度、减少动态效果、系统较大文字与屏幕缩放；核对无文字遮挡、无截断主操作，必要时可滚动。
- 从“应用程序”首次启动后，在快捷指令查找五个动作及四个预设；后台查询、应用未启动时调用、模式参数、状态字段条件判断，以及打开独立面板。
- USB 缺失、占用、切换失败、快速重复运行、UI 与快捷指令同时操作；确认错误不会提前变绿，也不会写入相反模式。
- 本机锁定时执行模式动作应遵守系统解锁要求；在已配置的 Siri 语言环境验证带应用名的短语。Siri 可用性和系统发现行为须以实际系统为准。
